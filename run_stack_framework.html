rcs · 充电枪抓取-插拔任务 | 框架结构与运行流程

PythonMuJoCoArUco 视觉伺服单线程确定性内核 + 旁路线程 —— 一个自定义的「进程内 ROS2-lite」微内核，控制器 / IK / 视觉 / 安全 / 显示均为协作式节点。

一、代码分框架

1.3 两类节点

类别节点执行模型数据交接
主循环（threaded=False） SimNode · ArmController · IKService · GraspNode · PoseNode · ChargingAction 每控制拍（50Hz）由 Executor 按 add 顺序调 on_tick() 依赖拍序，确定性；命令经 topic 传递
旁路线程（threaded=True） RenderNode · VisionNode · SafetyNode 各自 worker 线程，独立节流（渲染/视觉 10Hz、安全每帧） 产数据到 topic.latest；主循环轮询读取

二、启动 /scripts/run_stack.py 的运行流程

1
CLI 解析
  • python -m scripts.run_stack [--task charging] [--scene ...] [--vision] [--cams] [--safety] [--viewer] [--ticks N]
  • --render 缺省自动推断：任一图像消费者（cams/vision/safety）开启则开，否则关
2
GL 后端选型 _gl_backend()
  • Linux 无 DISPLAY 且未设 MUJOCO_GL → os.environ["MUJOCO_GL"]="egl"（离屏渲染）
  • 必须在 import 任何 gl_context 之前生效（后端在模块级一次性绑定）
3
组装节点栈 build_charging_stack(scene_xml, vision, render, viewer, cam_show, safety)
  • 创建 SimClock, Bus（全系统共享）
  • 按数据依赖顺序实例化主循环节点：SimNode → ArmController → IKService → GraspNode → PoseNode → ChargingAction
  • render 开启 → RenderNode(cam_e2h→/image_e2h) + RenderNode(cam_eih→/image_eih)
  • vision 开启 → VisionNode(e2h→/ee_pose_vision) + VisionNode(eih→/target_fine)，订阅各自图像话题
  • viewer/cam_show → ViewerNode / CamShowNode（含 overlays 检测框叠加）
4
Executor(dt=0.05) 注册节点 add()
  • 主循环节点入 _nodes；旁路线程节点（threaded=True）入 _threaded 并立即 start() 启动 worker 线程
5
下发目标 task.send_goal({...})
  • 充电任务 _build_phases()：构造 16 子段显式 Phase 状态机，激活枪焊死约束 eq_socgun_1
6
主循环推进 executor.spin(...)
  • 无显示窗口：全速跑、--ticks 为拍数上限，任务终态退出；有窗口：1x 实时、关窗退出
7
单拍 spin_once() = 确定性依赖序列
  • ① 主循环节点按序 on_tick()：任务推进 → 控制闸门 → IK 服务 → 抓取 → 位姿聚合 → 物理步进
  • ② 到期定时器（Camera/Vison/CamShow 的 GUI 节流）
  • ③ clock.advance(dt) 推进仿真时间
8
旁路线程并行（渲染 / 视觉 / 安全）
  • RenderNode：GL 线程渲染 cam_e2h/cam_eih → 图像话题（跳帧不积压）
  • VisionNode：ArUco 检测 + PnP + 标定板→目标物偏差补偿 → /ee_pose_vision、/target_fine，周期日志
  • SafetyNode：颜色分割检测黄色标识物 → /safety_state（喂给 ArmController 闸门）
9
结束 executor._shutdown()
  • 先停主循环节点，再 shutdown() 旁路 worker（Join 等渲染/视觉线程收尾释放 GL）
